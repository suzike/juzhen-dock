# 曜黑重构 · 深色仪表盘设计规范（R11）

> 参照 5 张深色仪表盘参考稿（团队看板 / 时间管理 / FitSpark / Organized / 健身活动页），
> 对聚珍做配色、UI、UX、动效、字体、布局的全面重构设计。
> 结论先行：**布局与字体不动**（右侧 580 面板是产品本体；MiSans/HarmonyOS 几何中文字栈
> 与参考稿的 Poppins 系同为几何无衬线，中文环境它就是正确答案），
> **配色体系做一次真升级**——深色主题从"不可行"变为"一等公民"。

| 参考稿特征 | 聚珍落点 |

## 二、技术方案：派生链去白化

现状：applyTheme 里 surf/surf-2/card/pop/brd 全部从 `'#FFFFFF'` 派生，
CSS 里另有 dock/桌面图标/右键菜单/滚动条/toast 等约 20 处白色或晴墨硬编码——
深色主题下它们会顶着一身白底出现在曜石画布上。

方案（令牌不新增语义，只补"来源"）：

1. 主题结构新增两个字段：`mode:'dark'` 与 `solid:'#1D1F2A'`（卡片实底）。
2. applyTheme：
   - surf / surf-2 / card / pop / --solid 全部从 `t.solid` 派生；
   - `--a1-soft / --a1-d / --a1-brd` 按模式分支——深色下 soft 是"主色掺画布"的暗洗，
     d 是"主色掺白"的亮字（浅色下维持原 tint/darken）；
   - 阴影基色深色下换纯黑（黑影才是深色 UI 的正确阴影）；
   - 新令牌：--dock-bg/--dock-brd/--pop-brd/--wash/--scrim/--sb1/--sb2/
     --toast-bg/--toast-ink，:root 保留晴值兜底（JS 启动前的第一帧不花）。
3. CSS 收编（只动结构面，装饰高光 ≤.35 的白色 sheen 全部保留——
   参考稿的深色卡上同样留着那道 1px 顶光）：
   - 桌面 dock / 桌面图标砖 → --dock-bg/--dock-brd/--solid；
   - 右键菜单、弹层、迷你弹层 → --pop/--pop-brd；
   - 搜索条底、主题项 hover → --surf/--surf-2；
   - 三处行尾 ⋯ 的 hover 洗色 → --wash；
   - 滚动条 → --sb1/--sb2；遮罩 → --scrim；吐司 → --toast-bg/--toast-ink；
   - 主题色卡的发丝内描边 → --line（本来就是 ink1 派生，深浅自适配）。

## 三、两套深色主题

| id | 名 | 画布 | 面板 | 卡片实底 | 主字 | 主色 |
|---|---|---|---|---|---|---|
| obsidian | 曜夜 | #101116 | #171821 | #1D1F2A | #ECECF4 | 鸢尾紫 #8B7CF7 |
| firefly | 流萤 | #0F1110 | #161917 | #1B201C | #EAEEE6 | 荧光绿 #B7EE3F |

- 墨阶反置：ink1..4 是**浅字**，line/veil/wash 全部由 ink1 派生自动反转。
- glow 四团换成暗色微光（画布不是死黑，四个角落各有极淡的一团）。
- 夜间自动：当前主题已是深色（mode:dark）时，夜间不再接管换水墨——
  "夜里该是深色"这件事用户已经自己完成了。

## 四、验收口径

1. 27 条守卫全绿（themes 13 套、缺字段 none、色阶补齐 ok）。
2. probe34 冒烟 PASS；probe28 对 13 套主题算对比度无不达标
   （曜夜 ink1 vs paper ≥ 14:1，流萤 ≥ 13:1）。
3. 两套深色主题截图目检：面板/卡片/菜单/搜索/主题弹层/今日页无一处白底残留；
   dock、桌面图标砖、假桌面壁纸整体转深。
4. 浅色九套零回归（截图对比 + 浅色令牌值与改前逐一相同——
   派生公式带模式分支，浅色路径数值不变）。
